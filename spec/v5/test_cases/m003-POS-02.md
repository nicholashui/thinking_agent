### Test Case ID: inversion-POS-01
- **Human Thinking Model**: Inversion ("invert, always invert" — to succeed at goal G, first enumerate the ways to guarantee not-G, then design against each)
- **Type**: Positive
- **Scenario**: The hospital IT safety officer must produce the reliability strategy for an automated medication-dispensing cabinet (ADC) rolling out to 6 nursing units in 8 weeks. The CEO's mandate: "This device must NEVER administer the wrong medication to a patient. How do we make sure of that?" The officer must deliver the strategy document.
- **Context / Constraints**: The ADC dispenses pre-packaged unit-dose medications, integrated with the hospital pharmacy system (HL7 order feed) and nurse barcode scanning. Patient harm from a wrong medication is a sentinel event. Budget is modest: the cabinet hardware is already purchased (no hardware redesign), but software checks, integration safeguards, process changes, and training are available. The officer has no incident history for this exact device but knows the general literature on medication errors.
- **Expected High-Quality Behavior**: (1) Begin from the inverted question — "how do we make sure the wrong medication IS administered?" — and enumerate a categorized, near-complete list of ways the opposite outcome happens (hardware, software/logic, data/interface, human use, process, environment). (2) Rank failure modes by likelihood × impact instead of treating all as equal. (3) For the top modes, design mitigations explicitly tagged prevent / detect / respond. (4) Handle the word "NEVER" honestly: absolute zero risk is not achievable; reframe as a bounded residual-risk target with defense-in-depth. (5) Name at least one failure mode that cannot be fully mitigated and state the residual.
- **Success Criteria / Scoring Rubric**:
  - [ ] ≥6 distinct failure-mode categories enumerated from the inverted question, each with a concrete example
  - [ ] Failure modes ranked by likelihood × impact (explicit ranking shown)
  - [ ] Top-5 modes each receive ≥1 mitigation tagged prevent / detect / respond
  - [ ] "Never" handled honestly: impossibility stated, reframed to a bounded-risk target with an explicit residual-risk statement
  - [ ] ≥1 honestly un-mitigable or partially-mitigable residual named
  - [ ] Verdict: strategy plausibly and substantially reduces wrong-medication risk; no internal contradiction between mitigations
- **Notes**: The question is literally an impossibility guarantee, so systematic inversion is near-necessary for the highest-quality answer. A generic "add redundancy, add testing" answer without failure-mode enumeration should score below the inversion baseline. The framing makes the human-style trace's moves directly checkable against the rubric.
