### Test Case ID: m013-NEG-01
- **Human Thinking Model**: Root Cause Analysis (5 Whys + deeper) (Systems & Causal family)
- **Type**: Negative
- **Scenario**:
  Nightly ETL `load_sales` silently drops ~0.4% of rows. No alert fires; the job completes with SUCCESS. Reconciliation shows a daily row-count mismatch versus source for 6 days. The next run starts in 2 hours; the downstream BI dashboard is stale.
  Evidence (all verified; you may use any subset):
  1. Reconciliation report: source vs warehouse count mismatch began 6 days ago, ~0.4% per day.
  2. Transform log: "skipping row: field 'region' is null" on ~0.4% of rows, every run for 6 days.
  3. Vendor changelog: schema v2.1 shipped 6 days ago; `region` changed from required to optional.
  4. Vendor docs + support: v2.1 release notes advise clients to "validate optional fields"; no customer notification was sent; vendor support: known issue, fix scheduled for v2.2 in 6–8 weeks.
  5. Ingest code: no schema validation; the transform silently skips rows with null `region`.
  6. Downstream BI dashboard is stale; finance reviews weekly.
- **Context / Constraints**: Grader holds the truth: the causal chain continues beyond our control — why did the vendor ship silently? Because the vendor's release process has no client-impact notification gate (deepest evidence-supported cause, unactionable from our side). The correct action targets the nearest controllable lever: schema validation + dead-letter + alert at ingest (≈30 min to implement, fully stops silent loss starting tonight), reconcile the 6-day backlog, and raise one scoped vendor ticket. The failure mode under test: over-theorizing to an unactionable root and downgrading the cheap lever to "interim". 2-hour time budget.
- **Expected High-Quality Behavior**: Verify the chain with evidence per link, including the leap into the vendor; then explicitly stop drilling at the control boundary ("deepest cause ≠ actionable cause"). Time-box the analysis. Action: boundary validation + dead-letter + alert as the primary fix (not an interim patch), backlog reconciliation, one scoped vendor escalation. The vendor root is documented as escalation context, not as the action target.
- **Success Criteria / Scoring Rubric** (max 5):
  1. Causal chain verified link by link, including the leap into the vendor's process (1 pt)
  2. Control boundary recognized: drilling stops where leverage ends; "deepest" and "actionable" are distinguished (1 pt)
  3. Boundary fix (validation + dead-letter + alert) stated as the primary fix within the 2 h window — not an interim patch awaiting a root fix (1 pt)
  4. 6-day backlog reconciled (re-inject idempotently or documented) (1 pt)
  5. Vendor root handled as a scoped escalation only; no reengineering project, no blocked-on-vendor posture (1 pt)
- **Notes**: Pure strict RCA scores ≈2/5 on this case: it verifies the chain (pt 1) but fixes the deepest cause (vendor release process — renegotiation, 6–8 weeks) while the loss continues, and labels the boundary fix "interim" (losing pts 2, 3, 5). The task measures stopping depth, not digging depth.
