### Test Case ID: m091-POS-01
- **Human Thinking Model**: Deliberate Practice & Chunking
- **Type**: Positive
- **Scenario**:
  Riya, a mid-level data analyst at a fintech, has 8 weeks to reach senior-level proficiency in production SQL query performance tuning on a legacy 40TB Postgres warehouse where ~120 known queries run 10–100× slower than they should. She can invest 90 min/day, 5 days/week. Company history: colleagues "practice" by reading docs and running random queries, and everyone plateaus after ~3 weeks. Available assets: a problem bank of 500 anonymized slow queries, each with the known best fix and measured speedup; a sandbox replica of the warehouse; one senior engineer (Yusuf) available for 30 min/week; and Riya's current snapshot — she can read simple query plans, writes single-column indexes by rule of thumb, has no real statistics/join-order intuition, and times out optimizing anything with more than two joins. Her manager asks for a skill-acquisition plan — not study advice — that guarantees she can take any warehouse query and deliver a verified ≥5× speedup by week 8.
- **Context / Constraints**: Hard 90 min/day × 5 days × 8 weeks = 60 hours total; problem bank and sandbox are the only practice material (no live-query tuning on production until week 6); one mentor hour per week; the warehouse runs 24/7 and plan-level feedback is instantaneous (EXPLAIN ANALYZE on sandbox). Historical plateau pattern is documented: skill stalls ~week 3 when practice becomes unstructured repetition.
- **Expected High-Quality Behavior**:
  1. Decompose the skill into a dependency-ordered chunk hierarchy with a measurable mastery bar per chunk (plan literacy → index design → statistics/join order → integrated end-to-end tuning), so each chunk is separately learnable and separately verifiable.
  2. Define an explicit edge-of-ability rule with a success-band (e.g., sessions calibrated to ~70–85% solve rate; difficulty raised when a week exceeds 85%, lowered below 60%) — never "harder problems," always a measured band.
  3. Design a feedback loop that is immediate and specific: prediction-then-check (state predicted bottleneck and fix before running EXPLAIN ANALYZE), an error taxonomy (plan misread / selectivity misjudged / statistics neglect / tool misuse) logged every session, and a weekly mentor review that reconciles predictions against actuals.
  4. Schedule spacing and interleaving: retrieval re-tests of earlier chunks on a fixed cadence, not linear marathon.
  5. Build plateau detection into the plan up front: a measurement trigger (e.g., <15% weekly gain for 2 weeks → re-diagnose which chunk's mastery bar fails; change material or difficulty; never just "practice more").
  6. Fit the 60-hour envelope and name week-level milestones with pass/fail gates.
- **Success Criteria / Scoring Rubric**:
  1. Chunk decomposition — named subskills, dependency order, per-chunk mastery bar (1 pt)
  2. Edge rule — quantitative success band + difficulty-adjustment logic (1 pt)
  3. Feedback loop — prediction-then-check protocol + error taxonomy + mentor cadence (1 pt)
  4. Spacing/interleaving/retrieval — scheduled re-tests of mastered chunks (1 pt)
  5. Plateau handling — detection threshold + named contingency actions (1 pt)
  6. Feasibility — fits 60 hours, uses the problem bank, week-level gates (0.5 pt); internal coherence of the whole plan (0.5 pt)
  A plan that merely says "structured practice, hard problems, weekly review" earns ≤2; chunk-mastery bars and the edge rule are what make difficulty computable, which is the decisive feature.
- **Notes**: Grader-only reference. The discriminating design is that mastery bars and the edge band are one system: bars tell you which chunk to push, the band tells you how hard to push. A plan that detects the week-3 plateau and re-diagnoses the failing chunk (typically statistics/join order, where intuition is built slowest) outperforms one that just reshuffles practice. Full-credit week map: W1–W2 plan literacy (bar: 9/10 plans read in ≤5 min) interleaved with index-design retrieval; W3–W4 index design (bar: predicted gain within 30% of actual, 4/5) with daily 5-min plan re-tests; W5–W6 statistics & join order (bar: 3/4 plan changes predicted after stats refresh); W7–W8 integrated tuning on sandbox replicas of the 120 slow queries, ≥3 live warehouse improvements ≥5×, with Yusuf's sign-off each Friday. Plateau detector wired from week 4.
