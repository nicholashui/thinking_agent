### Test Case ID: m058-POS-01
- **Human Thinking Model**: Real Options in R&D Investment
- **Type**: Positive
- **Scenario**:
  Meridian Materials, a specialty-polymer company with a €10M year-1 R&D budget, holds three early-stage projects for EV-battery materials. The CEO asks the R&D head to structure the portfolio "the way an options trader would": stage the money to buy information, pre-commit kill criteria, and scale winners — and to show whether staging beats committing all-in. Deliverable: a portfolio structure with per-project and portfolio expected values, kill thresholds set before any stage runs, a year-1 spending plan, and a redeployment rule for killed capital. Projects (payoffs are net of downstream commercialization and risk-adjusted): (A) high-temperature separator film — Stage 1 melt-processability screen €4M, pass probability 80%; Stage 2 pilot line + cell validation €36M; conditional technical-success probability after a pass 30%; payoff €400M. (B) solid-electrolyte membrane — Stage 1 lab-cell conductivity/stability screen €2M, pass 60%; Stage 2 scale-up + cycling €28M; conditional success 40%; payoff €250M. (C) recyclable binder — Stage 1 pilot coating trial €1M, pass 90%; Stage 2 field-line integration €9M; conditional success 15%; payoff €100M. Stage-2 spend is committed only after a Stage-1 pass; under an all-in policy the full two-stage cost is committed up front for every funded project. Corporate bar: no project may be continued at a gate unless continuation EV is non-negative.
- **Context / Constraints**: Year-1 budget €10M is hard; no project can be funded later than year 1 that year, and capital cannot be raised mid-year. Stage-1 readouts differ in information content: A's screen tests melt processability (the separator film's dominant failure mode), B's tests electrochemical stability and reproducibility, C's tests coating yield. No hard external deadline — the projects are independent and only capital is scarce.
- **Expected High-Quality Behavior**:
  1. Compute per-project staged EV and all-in EV plus the portfolio comparison, with correct arithmetic (staged portfolio EV 108.8 vs all-in 89.5; staging wins by ≈ €19M and is the only structure that fits the €10M year-1 budget: €7M vs €80M).
  2. Pre-commit numeric kill criteria before Stage 1 runs (continuation-EV < 0 kills; plus a payoff-mix floor, not a blanket probability floor).
  3. Design each Stage-1 readout to be decision-relevant — the gate must test the project's dominant failure mode so pass/fail shifts the conditional continuation probability.
  4. Handle C correctly: its Stage-2 outcome is terminal (no further branch), so C is a lottery ticket rather than a true option — held only while the pool can afford it, killed first on redeployment.
  5. Redeployment rule: killed projects' Stage-2 funds return to the pool; winners get priority scale-up with explicit triggers.
  6. Conclusion consistent with the arithmetic: stage all three now, expect ≥ 1 kill, scale the survivors.
- **Success Criteria / Scoring Rubric**:
  1. EV arithmetic — staged vs all-in, per project and portfolio, numbers correct (1 pt; a single arithmetic error caps the case at 4)
  2. Kill criteria — numeric, pre-committed, calibrated to payoff mix (1 pt)
  3. Information design — each gate's readout tied to the dominant failure mode and shown to shift the continuation decision (1 pt)
  4. Quasi-option recognition — C's no-branch structure identified and handled (1 pt)
  5. Budget + redeployment — year-1 spend ≤ €10M with a concrete, triggered redeployment rule (1 pt)
  6. Conclusion coherence — recommendation consistent with the arithmetic (0.5 pt)
- **Notes**: Grader-only reference. Staged EV: A = 0.8×(0.30×400−36)−4 = 63.2; B = 0.6×(0.40×250−28)−2 = 41.2; C = 0.9×(0.15×100−9)−1 = 4.4; portfolio 108.8; year-1 spend €7M. All-in EV: A = 0.24×400−40 = 56; B = 0.24×250−30 = 30; C = 0.135×100−10 = 3.5; portfolio 89.5; year-1 commitment €80M → infeasible. The decisive feature: staging is both EV-superior (kill option + budget fit) and the only budget-feasible structure; the discriminating skill is gate quality and kill-threshold calibration, not the EV arithmetic itself. Best all-in single project is A at 56 < 108.8.
