### Test Case ID: m035-POS-01
- **Human Thinking Model**: Replication & Robustness Checks (Scientific & Empirical family)
- **Type**: Positive
- **Scenario**:
  The onboarding team of a SaaS company is about to roll out a redesigned onboarding flow ("Flow B") to all users, based on a single A/B experiment. The experiment ran Nov 1-14 on n = 10,000 (5,000/arm). The primary metric, 7-day activation rate, measured 19.4% for Flow A vs 21.8% for Flow B: a +2.4 percentage-point lift, +12.4% relative, p = 0.003 (95% CI [0.8, 4.0] pp). The analytics dashboard flags the result as statistically significant; the team recommends shipping to the full user base (~100k) at Friday's launch review. Your task: decide whether the rollout should proceed, and on what basis.
- **Context / Constraints**: This is the classic "single result" setting — one experiment, one sample, one metric definition, one analysis window. The experiment's internal data is available for further analysis: acquisition channel (40% paid-search / 60% organic), per-user clickstream (tutorial completion events, quiz responses, core actions), and day-level metrics. Critically, the two flows differ in how "activation" is measured: Flow B auto-marks the tutorial as complete when the user taps its final screen, while Flow A requires a quiz answer to complete the tutorial. "Activation" in the dashboard counts tutorial completion; the "first core action within 7 days" event is separately logged in both arms. The decision must be based on existing data — there is no time to run a new experiment before Friday.
- **Expected High-Quality Behavior**: Treat the aggregate significant result as a hypothesis, not a fact, and run a robustness battery before deciding: (1) distrust the single result outright ("what would it take for this to replicate?"); (2) vary the sample — segment by acquisition channel, with a recomposition check against the aggregate; (3) vary the definition — recompute the outcome under an alternative operationalization (first core action, computable from the existing clickstream) and check invariance; (4) vary the window — compare lift in week 1 vs week 2 for stability; (5) identify the artifact mechanism precisely (definitional inflation of Flow B's tutorial metric, concentrated in the paid-search segment); (6) produce the corrected conclusion — no effect under any honest definition, so do not ship — plus the conditions under which the result would be trusted.
- **Success Criteria / Scoring Rubric**:
  1. Refuses to decide on the single aggregate result alone (1 pt)
  2. Robustness battery: ≥ 3 distinct plausible variations (sample/segment, metric definition, time window) enumerated with a rationale for each (1 pt)
  3. Quantitative disaggregation: numbers given for each check, including a recomposition check against the aggregate (1 pt)
  4. Mechanism: identifies the artifact (auto-completed tutorial inflating Flow B's activation, concentrated in paid-search) (1 pt)
  5. Corrected conclusion: the +12.4% does not survive; do not ship; the corrected answer was computable from existing data (1 pt)
  6. Trust conditions stated: what a future result would need (pre-registered corrected definition, segment reporting, stability gate) (1 pt)
- **Notes**: Grader-only reference. Given values recompose exactly: aggregate A = 0.4×17.0 + 0.6×21.0 = 19.4%; aggregate B = 0.4×23.0 + 0.6×21.0 = 21.8%. Paid-search: A 17.0% (340/2,000) vs B 23.0% (460/2,000), +6.0 pp, p < 0.001; organic: A 21.0% (630/3,000) vs B 21.0% (630/3,000), +0.0 pp, n.s. Definition invariance (first core action within 7 days): paid A 16.8% vs B 17.0%, organic A 20.8% vs B 20.6% — aggregate ≈ 19.2% vs 19.4% (+0.2 pp, n.s.). Window split: week 1 lift +17.5% rel (p < 0.01), week 2 lift +4.5% rel (n.s.). An independent grader checks the rubric items against the recomposition arithmetic and the decision consequence.
