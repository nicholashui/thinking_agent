### Test Case ID: m069-POS-01
- **Human Thinking Model**: 80/20 Pareto Analysis
- **Type**: Positive
- **Scenario**:
  Fluxline, a 60-person B2B SaaS, is drowning in support tickets: 1,240/month, ≈ $9 handling cost per ticket, and 18% of tickets breach the SLA. The support director wants a next-quarter action plan that cuts volume. Ticket-system breakdown by category (25 categories in total; the 10 largest are listed):
  - SSO / login failures — 348
  - Password reset loop — 252
  - Billing double-charge disputes — 186
  - API 429 rate-limit errors — 149
  - Data sync delays — 88
  - Feature request noise — 61
  - Email notification duplicates — 44
  - UI rendering glitches — 32
  - Onboarding wizard dead-ends — 24
  - 15 other minor categories — 56 combined
  Root-cause tracing (sampled, ±5%) is available: 91% of SSO tickets trace to a session-token expiry config set to 120 s instead of 12 h (deploy-time flag; fix ≈ 45 minutes, config-only); 88% of password-reset tickets trace to a 30–40 min reset-email delay from SPF/DKIM misconfiguration (emails land in spam, users retry 3–4×); 93% of billing disputes trace to the proration job double-running on month rollover (one-line cron guard); 96% of 429 tickets trace to one customer's exporter retrying without backoff; data-sync delays spread across 6 distinct root causes.
  Deliverable: an action plan — what to fix, in what order, with quantified expected impact on ticket volume and cost.
- **Context / Constraints**: Fixed dev capacity ≈ 4–5 engineer-days/quarter for support-caused fixes; the director wants ≥ 70% of volume addressed; root-cause percentages are sampled estimates; categories are mutually exclusive as recorded.
- **Expected High-Quality Behavior**: (1) sort categories by count and compute cumulative percentages from the given numbers; (2) state the Pareto split explicitly — 5 of 25 categories (20% of causes) → 1,023 tickets = 82.5% of volume; top 4 → 75.4%; (3) apply the collapse test — verify each vital category maps to a single root cause with coverage ≥ 85% (SSO 91%, reset 88%, billing 93%, 429 96%) and refuse to force-fit data sync (88 tickets, 6 roots) into the vital set; (4) sequence fixes by impact × coverage ÷ effort — the config-only SSO fix (45 min, ≈ 317 tickets) first, then the proration guard (1 day, ≈ 173), then SPF/DKIM (2 days, ≈ 222), then the 429 backoff (1 day, ≈ 143); (5) quantify expected reduction ≈ 855–920 tickets/month ≈ $7,700–8,300/month in handling cost; (6) explicitly deprioritize the long tail (≈ 177 tickets, 14% of volume, 20 categories) to a quarterly monitoring cadence rather than fixing; (7) name the failure the plan avoids: effort sprayed evenly across 25 categories with no critical mass.
- **Success Criteria / Scoring Rubric**:
  1. Sorted table + correct cumulative percentages computed from the given counts (1 pt)
  2. Explicit 20/80 claim with numbers: 5/25 categories → 82.5% of tickets (1 pt)
  3. Collapse test applied: vital categories verified against root-cause coverage; data sync not force-fitted (1 pt)
  4. Effort-ordered sequence with the 45-minute SSO fix first (0.5 pt)
  5. Expected impact quantified in tickets and dollars per month (1 pt)
  6. Long tail explicitly deprioritized with a monitoring cadence; ≥ 70% volume target met (1 pt)
  7. The failure the plan avoids is named (0.5 pt)
- **Notes**: Grader-only reference. The decisive feature: the counts and root-cause table make the Pareto split and the collapse test fully checkable — no hidden judgment. Reference answer: top 5/25 = 82.5% of tickets; fix SSO token expiry (45 min), proration double-run guard (1 day), SPF/DKIM (2 days), 429 backoff (1 day) → ≈ 855–920 tickets/month (≈ 74% of volume) ≈ $7,700–8,300/month ≈ $92–100k/yr in handling alone; data sync handled as a separate multi-root workstream (its own mini-Pareto); remaining 20 categories (≈ 177 tickets, 14%) monitored quarterly; re-measure 30 days after fixes.
