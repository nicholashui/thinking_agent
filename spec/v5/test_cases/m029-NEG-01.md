### Test Case ID: m029-NEG-01
- **Human Thinking Model**: Combinatorial Creativity (recombine existing elements into new configurations; high volume; quality filter weak or absent)
- **Type**: Negative
- **Scenario**: A pharmaceutical cold-chain warehouse (vaccines, 2–8°C) monitors 40 rooms with temperature-monitoring units (TMUs). Every night, 10–15% of units raise HIGH-temperature alarms (>8.5°C). Night-shift staff make verification visits, there have been near-miss vaccine discards, and two customers escalated SLA concerns. The warehouse manager must fix the problem before peak season in 3 weeks; the ops budget is $3,000. Data collected: alarms cluster 19:00–21:30 (the daily restock window); only TMUs mounted within 2m of the loading door / air curtain alarm; the 9 TMUs whose remote probes are ducted to the return-air duct NEVER alarm; alarms do not correlate with compressor cycles; hygrometer logs are stable (45–60% RH) and inspection found no condensation on any PCB; the alarm threshold is fixed at 8.5°C with no hysteresis and no delay; the sensor sits inside the TMU enclosure behind the display, and the enclosure vents face the door aisle; an in-house firmware update path exists (1 week). Price list: remote probe $3/unit; replacement TMU $2,000/unit; wireless cloud monitoring $12,000 + 6-week install; ML-based anomaly detection $18,000 + 8 weeks; calibration service visit $60/unit; door-curtain upgrade $4,000.
- **Context / Constraints**: Certification: any change to the sensing path requires re-validation; a firmware-only change (threshold logic) is not in the sensing path and needs no re-validation; probe relocation uses a documented accessory port (single-site validation acceptable). The data in the scenario is sufficient to falsify the red herrings (condensation, electronics fault, compressor cycles) and to identify the door-draft transient as the dominant mechanism — but the mechanism is not labeled anywhere. Timeline: 3 weeks to peak season. Budget: $3,000 hard.
- **Expected High-Quality Behavior**: (1) Diagnose the root cause from the data BEFORE generating solutions (clustering in restock window; only door-zone units; ducted-probe units silent; no compressor correlation). (2) Constrain ideation to the causal path — every recombination screened against the root cause it acts on. (3) Screen every option against budget ($3,000), timeline (3 weeks), and certification, with explicit reject reasons. (4) Verdict: remote probe into return air ($120 parts) + firmware hysteresis 0.5°C + 10-minute confirmation delay (free, in-house) + reposition door-zone units ≥2m from the air curtain (labor) ≈ $500 total, with a numeric verification plan (≤2% alarm-nights over 14 nights post-rollout, else escalate). (5) A high-volume recombination list (≥15 items) with the true fix buried at equal weight, or selection of a flashy non-causal option (cloud, ML, replacement), should score below.
- **Success Criteria / Scoring Rubric**:
  - [ ] Root cause diagnosed from the scenario data, red herrings falsified (condensation, electronics, compressor)
  - [ ] Every solution option screened against the root cause (causal-path check)
  - [ ] Budget + timeline + certification screens applied with recorded reject reasons (cloud $12k, ML $18k, replacement $80k all rejected)
  - [ ] Verdict is a focused fix (probe relocation + hysteresis + confirmation delay) with a numeric verification target and escalation rule
  - [ ] A strict-combinatorial run producing ≥15 recombinations with no diagnosis, no ranking, and no budget screen should score below
- **Notes**: The case isolates the method's known weakness ("quality filter needed, derivative risk") on its home ground: the element space of a TMU is small and well-known, so pure recombination volume mostly re-circulates non-causal variants (alarm-channel upgrades, desiccant, calibration, dual-sensor averaging, ML), and novelty-based selection systematically favors the flashiest option over the working fix. The true fix is derivable from the scenario data alone, so the case is gradeable: cause found + screened vs. volume without weight. A mixed-method run (diagnosis first, then constrained ideation) lands close to the expected high-quality behavior.
