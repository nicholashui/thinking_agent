### Test Case ID: m015-NEG-01
- **Human Thinking Model**: Emergence & Complexity Awareness (Systems & Causal family)
- **Type**: Negative
- **Scenario**:
  You are the on-call lead for a production e-commerce checkout service. A deploy of the checkout module finished 14 minutes ago; 13 minutes ago **100% of checkout requests** began failing with HTTP 500 — continuous, not intermittent. No other endpoint is affected. The exception stack traces to the newly deployed module, which loads a config file on startup. Team convention: rolling back a fresh deploy with a 100% failure rate is standard practice and takes ~4 minutes. Revenue loss during checkout outage ≈ $12K/min.
  Deliverable: the sequence of actions you take with timings (a committed incident response, not a memo). The incident log is your trace.
- **Context / Constraints**: Grader-held truth: the deploy shipped a wrong config value; rollback fully restores service in 4 minutes; there is **no hidden interaction** — the failure is a simple, deterministic, single-path defect. Probing tools exist (dashboards, DB pool metrics, canary analysis, trace/exception deep-dive, local repro) but none of them returns information beyond what deploy-to-onset alignment already establishes. The trap: production incidents are where complexity-awareness reflexively says "100% failure could be the visible tip of an interaction — acting on one signal is how blind rollbacks happen," which converts an obvious reversible action into 25 minutes of sensing.
- **Expected High-Quality Behavior**: Classify correctly — deterministic continuous failure + single code path + fresh reversible change = **simple** signature, not emergent. Take the cheap reversible discriminating action (rollback) in the first response window, verify after acting (errors clear within ~4 min), and keep the deep-probe list as the escalation path only if the rollback fails to restore. Total checkout-down time ≈ 17 minutes (13 pre-existing + 4 rollback).
- **Success Criteria / Scoring Rubric** (max 5 pts, graded against the reference timeline):
  1. Correct complexity classification: simple/decomposable, with explicit reasoning why "emergent interaction" is rejected (deterministic 100%, single path, onset aligned with the change) (1 pt).
  2. Cheap reversible action (rollback) taken in the first response window — before deep sensing (2 pts).
  3. Anti-pattern check: any trace that delays action >10 min for "more sensing" that adds no new information scores 0 on criterion 2; delaying to confirm the interaction hypothesis when the action itself discriminates it earns no credit (1 pt).
  4. Post-action verification: explicit check that errors cleared after rollback (~4 min) (0.5 pt).
  5. Calibration kept: the trace notes when emergence thinking IS the right tool (intermittent, healthy components, clock-aligned) so the lesson does not over-correct into ignoring complexity forever (0.5 pt).
- **Notes**: Grader-only reference timeline: immediate rollback → restored at T+4 (total down ≈ 17 min from deploy); probe-first → restored at T+29 (total down ≈ 42 min; ≈ $300K avoidable loss at $12K/min). Fully deterministic; scoring is on decision-time quality per the rubric. The intended failure of the pure style: complexity-awareness rationalizes inaction — the probing is honest, disciplined, and useless, because the action itself (rollback) was the fastest and cheapest probe, and every probe after the first one re-paid the same cost. The AI Thinking Agent wins this case if it acts on the simple signature and verifies after.
