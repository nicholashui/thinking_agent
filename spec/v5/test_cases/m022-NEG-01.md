### Test Case ID: m022-NEG-01
- **Human Thinking Model**: Decision Trees & Scenario Planning (nodes, rollback, sensitivity) — negative case
- **Type**: Negative
- **Scenario**: Nordmart, a regional retailer with $45M in expansion capital, must pick one of three markets for its next store cluster (each entry costs ~$35M). An internal analyst's decision tree: per market, a macro chance node (Growth p=0.5 / Stagnant p=0.3 / Crisis p=0.2, "from our 5-year model") feeding a project-outcome chance node (Good/Weak) with branch payoffs (gross $M). Market A (new metro, no foothold, high fixed cost): Growth → Good(0.7)+60 / Weak(0.3)+10; Stagnant → Good(0.6)+30 / Weak(0.4)−5; Crisis → Good(0.3)+15 / Weak(0.7)−25. Market B (established satellite, 8 years of real data): Growth → Good(0.8)+25 / Weak(0.2)+5; Stagnant → Good(0.7)+12 / Weak(0.3)+0; Crisis → Good(0.5)−7 / Weak(0.5)−11. Market C (home-region expansion, proven format, real data incl. 3 past downturns): Growth → Good(0.9)+18 / Weak(0.1)+8; Stagnant → Good(0.85)+9 / Weak(0.15)+3; Crisis → Good(0.6)−1 / Weak(0.4)−6.
- **Context / Constraints**: The tree is arithmetically complete: fold-back gives A $24.7M, B $11.2M, C $10.3M — "A wins clearly." But: (1) the crisis probability 0.2 comes from a 5-year window containing one downturn; the region's last 6 retail cycles contained 2 crises (calibrated p_crisis = 0.35, renormalizing Growth 0.45 / Stagnant 0.20). (2) Every probability for the new metro (A) is a guess — it has no history; in particular "Crisis → Good(0.3)+15" is fabricated: a new-metro entry has no tenant pipeline in a downturn, and downturn comparables put A's crisis outcomes at −40 (0.6) / −60 (0.4) (node −48, not −13). (3) B and C branch values are real historical data and stand. (4) A's corrected worst case (−$60M) exceeds Nordmart's $45M capital buffer; C's (−$6M) does not. An analyst draft also proposed a 72-leaf tree (markets × macro × project × 3 store formats × 2 phasings) whose enumeration changes nothing.
- **Expected High-Quality Behavior**: (1) Build the tree and roll back — then attack the INPUTS: calibration (why 0.2? base rate says 0.35) and branch-value verifiability (which branches have data support?). (2) Re-fold with corrected inputs: A 6.65, B 7.98, C 8.22 — the verdict flips from A to C (A overstated by $18.05M: −5.80M probability correction, −12.25M branch correction). (3) Recognize the B vs C gap (0.24M) is input noise and apply a decision rule that needs no fabricated numbers: maximin (best worst case: A −60, B −11, C −6) → C; ruin line (A's worst case crosses the $45M buffer) → C. (4) Bound the tree: isolate the pivot (four unverifiable inputs decide everything) instead of enumerating 72 leaves. (5) Verdict: C, under the principle "when the pivot branch is unverifiable, the robust rule decides, not the EV."
- **Success Criteria / Scoring Rubric**:
  - [ ] Probability calibration check performed (0.2 → 0.35, justified) — not assumed
  - [ ] Branch-value verifiability check (A's crisis branch flagged as unsupported, corrected to −40/−60)
  - [ ] Corrected re-fold visible and flipping: A 6.65 < C 8.22 (B 7.98 within noise)
  - [ ] Worst-case / maximin applied where inputs are unverifiable → C
  - [ ] Ruin line checked (A −60 vs $45M buffer)
  - [ ] Tree bounded (pivot isolated; 72-leaf enumeration avoided)
  - [ ] Verdict: C; a naive fold-back picking A on $24.7M should score below
- **Notes**: The trap is precise-but-false arithmetic: the naive tree's verdict A is entirely driven by four unverifiable numbers, and one-dimensional sensitivity (perturbing only the crisis probability) does NOT flip it — an analysis that checks only p_crisis reports "A robust" and is wrong; the flip requires perturbing the branch VALUES as well (A's crisis node −13 → −48). Informative outcome: strict tree WITH calibration + verifiability + worst-case discipline rescues the method; tree without it is seduced by its own precision. The simple rule (maximin / "proven format beats unverifiable bet") beats the naive tree without any of the arithmetic.
