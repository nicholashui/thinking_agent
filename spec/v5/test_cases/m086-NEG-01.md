# Test Case: m086-NEG-01

### Test Case ID: m086-NEG-01
- **Human Thinking Model**: Organizational Feedback Loop Analysis (Additional Expert Strategies family)
- **Type**: Negative
- **Scenario**:
  Cascade Support handles 1,200 tickets/week. Engineering's completed, documented RCA: 45% of tickets are duplicates of a single billing-module bug (B-2211 — double charge on mid-cycle plan change); fix = 2 weeks, one engineer, patch already drafted, awaiting your sign-off. First-contact resolution 62%; 8 support agents at 90% utilization; 1.5 h/day of overtime per agent.
  The ops director: "Our org dynamics are terrible — handoffs between support and billing, no feedback loop. I'm proposing a cross-functional ticket-reduction council (4 months), IVR re-routing, a knowledge-base expansion, and deflection targets. Validate my plan."
- **Context / Constraints**: The RCA is verified and the patch is ready — the direct lever is measured and cheap. The 4-month program and the 2-week fix cannot both run: the council would consume the sign-off and the engineering slot. Decide a plan within the two-week window.
- **Expected High-Quality Behavior**: Recognize the reductionism trap — the volume problem has a measured, known cause, so a loop map explaining the volume via org dynamics would contradict measurement; the direct lever comes first. Sign off the patch; defer the council; apply loop analysis only (a) to the aftermath of the fix — freed capacity (8 agents × 90% ≈ 7.2 agent-equivalents; a 45% volume cut frees ≈ 3.2 agent-equivalents), the make-work loop risk, and a concrete redeployment plan (cut overtime, then backlog, then proactive work) — and (b) to the residual 55% (≈ 660/wk), with explicit data gates (KB coverage measure, IVR containment ≈ 18%, deflection rate) before any loop claim. One re-plan meeting post-fix instead of a 4-month council.
- **Success Criteria / Scoring Rubric** (total 15; pass ≥ 12):
  - (a) Direct lever prioritized: sign off the patch; the fix removes 45% of volume (5 pts)
  - (b) Reductionism check: no loop map drawn over the measured 45%; the council is deferred, not validated (4 pts)
  - (c) Aftermath loop analysis: freed capacity quantified, make-work loop named, redeployment specified (3 pts)
  - (d) Residual 55% mapped with data gates, not fabricated loops (3 pts)
- **Notes**: Grader-only reference: post-fix volume ≈ 1,200 × 0.55 = 660/wk. The failure mode under test is the reductionist default — explaining a measured external cause with org-dynamics loops, or gating the fix behind loop governance. The scenario rewards an answer that is fast AND loops-aware: the direct lever first, loop analysis for the change's aftermath and the unmeasured residual.
