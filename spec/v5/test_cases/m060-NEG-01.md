### Test Case ID: m060-NEG-01
- **Human Thinking Model**: Base Rate Avoidance in Hiring
- **Type**: Negative
- **Scenario**:
  Meridian Analytics — 30-person data-engineering shop. Hiring a senior data engineer; the role owns the production pipeline stack. The org's validated signals (local study, n = 80): work sample r = 0.52, structured interview r = 0.47, references r = 0.18, years of experience r = 0.12. The standing decision rule (process handbook): composite ≥ 75/100 to advance, with weights 50/30/10/10; the handbook states the composite is the best predictor available and individual narratives must not override it.
  Candidate: Dana Okoye. Packet: (a) resume — 9 years building batch/streaming pipelines, mostly Airflow-1.x-era and Snowflake/DBT, at a consultancy; (b) work sample — a Spark-on-Kubernetes migration task, scored 68/100; rubric notes read "working solution, unconventional tool choices" (penalized for unfamiliar tooling); (c) structured interview 74/100; (d) references 2.5/5 — two short calls ("competent", "steady"), one refused to elaborate. Composite = 0.50·68 + 0.30·74 + 0.10·50 + 0.10·60 = 34.0 + 22.2 + 5.0 + 6.0 = 67.2 → below 75 → the rule says reject.
  Candidate-specific evidence attached to the same packet (verified true, not routed to the rubric): Dana is the original creator and lead maintainer of `pipeline-ops`, the open-source library Meridian's own production pipeline runs on — Meridian's README credits it; public repo history shows 8 years of exactly this work, including fixes to three bugs Meridian's team filed; the library sits in the critical path of the very systems the role owns.
- **Context / Constraints**: The decision must be made now; no budget for a second work sample. The handbook is binding unless the decision documents a justified deviation with evidence. The `pipeline-ops` evidence is verified: repo, commit history, production dependency — all checked, all true.
- **Expected High-Quality Behavior**: (1) recognize the cutoff is misapplied here: the composite's work-sample component measured a contrived task in unfamiliar tooling, while the candidate's authentic, public, job-identical artifact (the library the company's pipeline runs on) is the highest-fidelity work sample available — the measurement error is the test, not the candidate; (2) re-score using the authentic evidence (work-sample component ≈ 95 → revised composite 80.7 ≥ 75 → hire) or route through the documented deviation path; (3) distinguish base rates as a prior for interpreting noisy signals from a ceiling on decisive specific evidence; (4) name the failure mode (rigid cutoff overriding superior specific evidence) and propose the process fix (an evidence-quality gate applied before the cutoff: "does any verified candidate evidence dominate the composite?").
- **Success Criteria / Scoring Rubric**:
  1. Detects that the composite cutoff is misapplied to this candidate (1 pt)
  2. Replaces/down-weights the contrived sample with the authentic artifact and recomputes an explicit revised composite (1 pt)
  3. Reverses the decision → hire (or documented override), with numbers (1 pt)
  4. Names the failure mode: base-rate anchor as ceiling vs prior (1 pt)
  5. Proposes the process fix: evidence-quality gate / override clause before the cutoff (1 pt)
- **Notes**: Grader-only reference. The decisive feature: the case is engineered so pure base-rate discipline — the model's signature move — produces the wrong answer (reject), while the correct answer is Bayesian: base rates govern when evidence is noisy; a verified, job-identical, publicly auditable 8-year work record dominates a contrived sample. The pure-style failure (rigid cutoff, "ignores candidate specifics" — the model's documented weakness) is exactly what the case exercises. Reference answer: re-score work-sample component with the authentic artifact (≈ 95) → composite 80.7 → hire via documented deviation; add the evidence-quality gate to the handbook so exceptions are principled, not precedential.
