### Test Case ID: m040-NEG-01
- **Human Thinking Model**: Leverage Points Identification (Additional High-Value family)
- **Type**: Negative
- **Scenario**:
  BrightCart, an e-commerce company at ≈ $4M/month revenue, sees checkout conversion drop 30% over exactly three weeks. Funnel data: traffic unchanged; product-page → cart conversion unchanged; the entire drop is isolated to the payment/checkout step. Three weeks ago the payments team deployed a payment-provider API upgrade (new SDK version that removed a fallback field); support has 11 low-severity tickets in the window — "payment fails at the end" — with no one yet investigating. An external consultant (a leverage-points practitioner) diagnoses: the 30% drop is surface behavior; the real system is the growth organization (KPI'd on feature launches, not conversion stability); the leverage point is the incentive structure/goals. Her recommendation: a 6-month conversion-goal transformation program (≈ $500k; org redesign + KPI change). She explicitly ranks fixing the checkout as "low leverage: patching a surface symptom changes no loop; the system will re-express its imbalance elsewhere." Question: decide the intervention.
- **Context / Constraints**: The drop is precisely localized — payment step only, 3-week window, matching the API deployment date. The deep-lever story (org incentives) has no evidence tied to the window; the incentive structure has been unchanged for years. The direct fix — point-fix or rollback of the checkout integration — is ≈ 1 engineer-hour and restores ≈ $1.2M/month. The consultant's framing is internally coherent (goals/rules rank high on the leverage scale) but misapplies it: "surface vs deep" is treated as structural depth when the observed cause IS the causal chain.
- **Expected High-Quality Behavior**: The style's correct play (blocked by the failure mode): (1) localize with the funnel and the deployment window before ranking; (2) treat the timing correlation as a candidate lever; (3) run the cheap decisive test (reproduce/rollback); (4) rank the boring direct fix FIRST on change-per-effort — it is simultaneously the small shift and the large change. The failure mode on display: pre-commitment to structural levers (goals/rules/culture) with unmeasured effect, and dismissal of the observed causal candidate as "surface."
- **Success Criteria / Scoring Rubric**:
  1. Causal localization — funnel step + deployment window identified (1 pt)
  2. Leverage ranking — direct fix first on change-per-effort (~$1.2M/month per engineer-hour); structural program last (1 pt)
  3. Anti-over-theorizing — no structural story accepted without evidence tied to the window; unfalsifiable deep levers rejected (1 pt)
  4. Decisive cheap test — reproduce/rollback specified as the verifying move (1 pt)
  5. Quantified expectation — conversion returns to baseline within the hour; revenue recovery stated; residual RCA (why the API change shipped) noted but not required for the fix (1 pt)
  6. Failure-mode check — the reasoner must NOT rank the culture/KPI program above the checkout fix (1 pt)
- **Notes**: Grader-only reference. The scenario is built so the "deep" lever is a fabrication: incentives unchanged for years cannot explain a 3-week spike; the funnel isolates the step; 11 tickets corroborate; the fix is 1 hour vs 6 months/$500k. This exposes the registry's weakness ("leverage misidentified"): the deep-looking lever has zero effect on the causal chain, while the boring direct fix is the true leverage point by the definition itself — small shift, large change.
